# Strategic vision

Nica-GeoFetch is intended to become a reproducible access and interoperability
layer for trusted institutional geospatial datasets relevant to Nicaragua. It
will grow in explicit stages so the project earns reliability before adding
surface area.

## Stage 1 - Reproducible downloader

Discover, download, validate, convert, and package institutional geospatial
datasets with provenance and checksums. MVP-1 implements this stage for one
INETER dataset family only.

## Stage 2 - Dataset registry

Maintain a structured catalog of sources, institutions, access protocols,
formats, licenses, provenance, availability, and quality status. The small
MVP registry is a seed for this stage, not a completed national catalog.

## Stage 3 - Standardized national base layers

Provide reproducible workflows for foundational datasets used by technical
users, researchers, universities, municipalities, NGOs, and public-interest
projects. Standardization must preserve source attribution and make every
transformation inspectable.

## Stage 4 - Interoperability layer

Expose normalized datasets through Python APIs, CLI workflows, catalogs,
metadata standards, and eventually lightweight services. Services come only
after downloader behavior, source governance, and normalized schemas are
stable.

## Stage 5 - DataNicaTools integration

Support domain applications and analyses in hydrology, climate, drought,
flooding, natural hazards, ecosystems, protected areas, agriculture and
AgTech, population, economy, health, infrastructure, and territorial planning.

Only Stage 1 is implemented in MVP-1. Stages 2-5 are direction, not current
capabilities or commitments to redistribute source data.
